What's actually hard

The vast majority of file edits fall into a few mechanical patterns:

  • <TargetFramework>net462</TargetFramework> → net10.0-windows in every csproj
  • RuntimeIdentifier win10-x64 → win-x64
  • WindowsTargetPlatformVersion made conditional (WDK 10.0.22621.0 → 10.0.26100.0 fallback)
  • Package upgrades for system libraries that moved out of the BCL
  • Removal of WUApiLib (Windows Update COM interop — not in .NET 10)

The hard part is NOT the framework bump itself — it is the dozen+ behavioral incompatibilities surfaced by .NET 10 that broke data-path tests. The Bug Fixes tab walks through each one.

Library / package upgrades

  • WCF (System.ServiceModel.*) 4.3.x → 6.2.0 — major jump; client APIs changed signatures. Watch ChannelFactory, MessageVersion.
  • BouncyCastle.Cryptography removed — PEM export now uses built-in System.Security.Cryptography APIs.
  • WUApiLib removed — gone in .NET 10. ~25 files excluded from compilation under Microsoft.Hcs/Update/ and Microsoft.Hcs/Setup/Service/.
  • System.Threading.Tasks.Dataflow 4.7.0 → 8.0.0 — newer dataflow blocks (DataUpload pipeline).
  • System.DirectoryServices 7.0.x — was a GAC reference, now a NuGet package.
  • System.ServiceModel AssemblyResolve shim — added to GMS startup for transitive references (commit d951d45641).

Native C++ changes

  • WDK 10.0.22621.0 → 10.0.26100.0 fallback in Directory.Build.props
  • Toolset auto-select: VS 2022 stays on v143, VS 2026+ gets v145
  • ucrtbased.dll path issue documented in new DevSetup.md
  • Several P/Invoke bool signatures fixed (see BUG 9)

Test infrastructure

  • New unit-test pipeline POD_UT_NET10 (ID 449371) — runs against .NET 10 binaries
  • Microsoft.Hcs.UnitTests.csproj retargeted to net10.0-windows-x64
  • xUnit + runner versions bumped; isolation logic changed in runtest.ps1
  • MockSaaS infra updated for new ServiceBus client behavior
  • New helpers added: MockSaasLogHelper.cs, DevSetup.md, local build scripts
